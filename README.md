# Генератор випадкових рецептів на вечерю

## Опис

Веб-застосунок, який пропонує випадковий рецепт страви на вечерю: показує фото,
категорію та інструкцію приготування, дозволяє фільтрувати власні рецепти,
зберігати улюблені рецепти (IndexedDB) і переглядати історію генерацій.
Інтерфейс — односторінковий (SPA) з hash-маршрутизацією, картка рецепта —
React-компонент, рецепти віддає локальний сервер на Node.js + Express.

## Запуск

```bash
cd server
npm install
npm start
```

Після запуску відкрийте http://localhost:3000

## Безпека (практикум 15)

### XSS

- **Аудит innerHTML.** Пошук по проєкту знайшов 4 використання `innerHTML` у `js/router.js`.
  Усі лише очищали контейнер сторінки рецепта (`innerHTML = ''`) і не підставляли жодних даних.
  Їх замінено на `replaceChildren()`, тож `innerHTML` у клієнтському коді більше немає.
- **Знайдена вразливість.** Поле `strInstructions` приходить із зовнішнього джерела
  (TheMealDB, з практикуму 14 — власний сервер). Під час додавання розбиття інструкції на кроки
  перша версія функції `renderInstructionSteps` вставляла кроки рядком через `innerHTML`,
  і тестовий рядок `<img src=x onerror="alert('XSS')">` в інструкції виконувався як код.
- **Виправлення.** Кожен крок тепер створюється через `document.createElement('li')`
  і заповнюється через `textContent`, тож HTML в інструкції показується як звичайний текст.
- **Інші місця з даними.** Назва, категорія й кухня рецепта, повідомлення про помилки
  та список улюблених виводяться через `textContent` або JSX у React-компонентах
  (React автоматично екранує текст, `dangerouslySetInnerHTML` не використовується).

### Сховища даних

- **IndexedDB** `DinnerRecipesDB` → сховище `favorites`: лише `id`, `name`, `imageUrl`
  улюблених рецептів. Особистих чи чутливих даних немає.
- **localStorage**: ключ `favorites` (копія улюблених з першого етапу практикуму 11)
  і прапорець `favoritesMigrated`. Чутливих даних немає; після міграції копія в localStorage
  вже не потрібна, і в реальному застосунку її варто видаляти, щоб не зберігати дані двічі.
- Паролів, токенів чи персональних даних застосунок не зберігає.

### Секрети в коді

- Реальних ключів і паролів у коді немає. Ключ «1» у TheMealDB (практикуми 9–13) —
  публічний тестовий ключ, а з практикуму 14 запити йдуть на власний сервер без ключа.
- `node_modules` виключено з репозиторію через `.gitignore`.
- Скрипти React і Babel завантажуються з CDN unpkg. Сторонній скрипт має повний доступ
  до сторінки й сховищ, тому для продакшн-версії варто фіксувати версії (уже зроблено)
  і додати атрибут `integrity` (Subresource Integrity) або зібрати застосунок без CDN.

### HTTPS

- Під час розробки застосунок працює на `http://localhost`, який браузер вважає безпечним.
- Для фінальної здачі потрібен хостинг з HTTPS за замовчуванням. Застосунок має сервер
  на Node.js, тому GitHub Pages (лише статичні файли) не підходить: обрано хостинг Node-застосунків
  з автоматичним HTTPS-сертифікатом, наприклад Render (Web Service).
- Усі сторонні ресурси (unpkg, Google Fonts) уже завантажуються по HTTPS, тож після
  розгортання не буде помилок змішаного вмісту (mixed content).
